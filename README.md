# TenantAuth

A self-hosted, multi-tenant identity provider built with .NET 10 and .NET Aspire. Think of it as a small, focused alternative to Auth0 or Keycloak: tenants, users and OAuth 2.0 / OpenID Connect clients, with an admin UI and an immutable security audit log.

> Status: Milestone 1, step 1 (solution skeleton). Services are added step by step.

## Getting started

### Prerequisites

- .NET SDK 10.0.301 or a later 10.0 feature band (pinned in `global.json`)
- Docker Desktop with the engine running

### Run

```bash
dotnet run --project src/AppHost
```

The console prints a link to the Aspire dashboard. The `postgres`, `identitydb` and `redis` resources should reach the **Running** state. The first run pulls the container images, so it takes a bit longer.

## Repository layout

```
src/
  AppHost/           Aspire orchestration: resources and their dependencies
  ServiceDefaults/   Shared service setup: OpenTelemetry, health checks, service discovery, resilience
tests/               Added when the first testable code lands
```

The Identity, Api and Web projects are added in the steps that need them.

## Design decisions

**.NET Aspire for local orchestration.** One command starts every service and its dependencies, wires connection strings automatically, and gives a dashboard with logs, traces and metrics. The same model is used later to deploy to Azure Container Apps with `azd`.

**PostgreSQL and Redis run as containers, not managed Azure services.** `AddPostgres` and `AddRedis` start containers locally and become container apps when deployed. Managed offerings such as Azure Database for PostgreSQL or Azure Cache for Redis cost money even when idle, and this project is designed to run at zero cost.

**No hard-coded secrets.** The PostgreSQL password is generated by Aspire and stored in user secrets locally. Nothing sensitive lives in `appsettings.json`.

**Central build settings in `Directory.Build.props`.** Target framework, nullable reference types, implicit usings and `TreatWarningsAsErrors` are set once and apply to every project, including ones added later.

**Central Package Management (`Directory.Packages.props`).** Every NuGet version is declared in one file, so all services use the same versions, upgrades are one-line changes, and new dependencies are easy to review.

**SDK pinned with `global.json`.** Local machines and CI build with the same SDK. `rollForward: latestFeature` allows newer 10.0 patches and feature bands but never a preview or a new major version.

**Resource names are lowercase.** PostgreSQL folds unquoted identifiers to lowercase and Azure Container Apps requires lowercase names, so `postgres`, `identitydb` and `redis` work the same everywhere.
